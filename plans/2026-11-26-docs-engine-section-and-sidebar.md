# Docs: an Engines section and a sidebar that follows the reader's path

## Goals

- The top page (#2510) now leads with Wvlet's own engine and a choice of engines, but the docs still file the engine as "Usage > Connector - Wvlet Engine", one 400-line page among 15 alphabetized usage pages.
- A new reader should be able to walk the sidebar top to bottom: get started, learn the language, pick an engine, connect tools, contribute.
- The engine gets a section of its own that answers what it supports, how fast it is against DuckDB (honest numbers), how to try the GPU executor, and (later) how to embed it.

## Background

- The sidebar is autogenerated from folders: Introduction, For AI Agents, Usage (install, CLI, REPL, UI, VS Code, playground, every connector, remote server, catalog import), Query Syntax, Language Bindings, Development.
- Docusaurus derives URLs from file paths, so a sidebar change alone keeps URLs, while moving a file changes its URL. There is no redirect plugin yet; `onBrokenLinks: 'throw'` catches broken internal links at build time.
- Links into the engine pages that move: `for-ai-agents.md` (engine, DuckDB, Trino), `syntax/flow.md`, `syntax/model-pipelines.md`, `usage/playground.md`, and `usage/ui.md` (to `#tpc-h-tables`). Outside the docs, the top page, old blog posts, and one example README link only to pages that stay (`usage/install`, `usage/repl`, `usage/ui`, `usage/trino` in a blog post). No test reads `website/docs/usage/` paths.
- `onBrokenMarkdownLinks` is `warn`, so a stale relative link would not fail the build; the build log has to be checked.
- `docusaurus-plugin-llms` orders `llms-full.txt` by folder globs (`for-ai-agents.md`, `index.md`, `syntax/**`, `usage/**`, `bindings/**`).
- A parallel session is rewriting `docs/index.md` and `syntax/quick-start.md`, so this work must not move or edit those two files. An explicit sidebar lists them by id without editing them, and their links (install, REPL, VS Code) do not move.
- Performance claims must come from current benchmark numbers (goal rule). The SF10 dashboard's latest run is #2505 (2026-11-27 UTC, M5 Pro): TPC-H 1.41x DuckDB total (geomean 1.39x), TPC-DS 1.20x (1.11x), much closer than the 2026-11-24 note (3.78x, 2.36x).
- The GPU executor is an example module: JVM-only, not in the CLI pack or CI, and reachable only through sbt tests and a bench (`GpuTPCHTest`, `GpuTPCHBench`). Its ADRs record the DGX Spark numbers and limits.

## Design

Lane: Express — docs only, no always-gate area; the redirect plugin is a docs-site dependency.

- **Sidebar order** (explicit `sidebars.ts` instead of autogeneration), each a category:
  - Get started: Introduction, Installation, Quick Start, Playground, Interactive Shell (`wv`), For AI Agents.
  - Language: the `syntax/` pages as today (Quick Start moves to Get started).
  - Engines: Choosing an engine (new overview), Wvlet Engine (sub-category), DuckDB, Trino, Snowflake, Working with multiple connectors, Remote server, Importing catalogs.
  - Tools and integrations: CLI (`wvlet compile`), CLI reference, Web UI, VS Code, Slack, Language bindings. The request lists VS Code, UI, Slack, and bindings; the CLI pages join them because they are tools, not engines, and Remote server and Importing catalogs sit under Engines because they configure where queries run.
  - Contributing: the `development/` pages.
- **Move only the engine pages**: `usage/{wvlet-engine,duckdb,trino,snowflake}.md` go to `docs/engines/`, so engine URLs read `/docs/engines/...`. Everything else keeps its file and URL; the sidebar alone regroups it. This keeps churn and conflicts with the parallel session low.
- **Redirects**: add `@docusaurus/plugin-client-redirects` with one entry per moved URL; `/docs/usage/wvlet-engine` goes to the engine overview. The old per-page `.md` copies for agents (`/docs/usage/wvlet-engine.md`) will 404; `llms.txt` lists the new ones, so we accept that.
- **Inbound links** listed in Background are rewritten to the new pages, with anchored links (`#tpc-h-tables`) pointing at the sub-page that now holds the section. `for-ai-agents.md` changes only link targets, so the bundled skill needs no update.
- **Wvlet Engine sub-category**, split from the current page (content kept, retitled from "Connector - Wvlet Engine"):
  - Overview: what it is, where it runs (JVM, Native, Node.js/browser), supported and unsupported features, functions.
  - Tables and files: registering tables, built-in tpch/tpcds catalogs, saving, creating, changing, persistent tables, files, Iceberg (the bulk of today's page).
  - Performance: TPC-H and TPC-DS at SF10 vs DuckDB (and DataFusion / Trino as references), total and geomean, with the commit, date, and machine, and where the engine is slower. Numbers come from the latest SF10 dashboard run, not the 2026-11-24 note.
  - GPU executor (experimental example): what offloads, how to run its sbt test and bench on a CUDA machine (no CLI path), the DGX Spark TPC-H SF10 numbers with their CPU-engine and DuckDB baselines from the same runs, and its limits.
  - Embedding: a short placeholder that says it is planned and links to the bindings, to be filled by the embedded-library item.
- **Choosing an engine** overview: one short table of engines (Wvlet CPU, Wvlet in the browser / Node.js, Wvlet GPU, DuckDB, Trino, Snowflake) with when to pick each and the `-t` / profile to use. Claims only what the code and ADRs back.
- **llms.txt order** follows the sidebar: `for-ai-agents.md`, `index.md`, `usage/install.md`, `syntax/**`, `engines/**`, `usage/**`, `bindings/**`.
- **Two PRs**: (1) sidebar, moves, redirects, link updates, engine split, overview, GPU and embedding pages; (2) the performance page from the latest SF10 dashboard run, kept separate so its claims get their own review.

## Alternatives and Why Not?

- **Move every page into new folders** (`get-started/`, `language/`, `integrations/`, `contributing/`): URLs would match the sidebar, but it renames ~40 URLs, touches the parallel session's files, and breaks top-page and blog links for little reader benefit.
- **Sidebar only, move nothing**: zero redirects, but the promoted engine would still live at `/docs/usage/wvlet-engine`, which undercuts the engine-first story in shared links.
- **Keep the engine as one long page**: simplest, but performance, GPU, and embedding would push it past 500 lines and bury the overview.
