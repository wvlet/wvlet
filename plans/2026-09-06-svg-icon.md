# Provide a scalable SVG version of the Wvlet icon

- Author: Taro L. Saito
- Date: 2026-09-06

## Context

The Wvlet icon (the teal/gray "W" mark) exists only as raster PNG/ICO files under
`logos/` (mirrored in `website/static/img/logos/`, `wvlet-ui-main/public/img/`,
`wvlet-ui-playground/public/img/`, `vscode-wvlet/icon.png`, `website/static/img/logo.png`).
The only SVG under `website/static/img/logo.svg` is the unused Docusaurus template dinosaur.
Raster icons blur on high-DPI displays and cannot be recolored or resized cleanly.

Goal: add a hand-crafted, scalable `wvlet-icon.svg` that reproduces the PNG's style,
shape and gradients as closely as possible, and use it where the web surfaces render the icon.

## Findings from exploration

- `logos/android-chrome-512x512.png` is the ground truth (512x512, RGBA, transparent background).
  Pixel measurement shows exactly four sheared parallelogram strokes, no shadow/outline:
  - two teal strokes (`\` direction), two gray strokes (`/` direction), teal drawn on top of gray
  - stroke width ≈ 90px, vertical extent y ≈ 134.5 → 377 (height ≈ 242), horizontal shear ≈ 104px
  - teal tops at x ≈ 38 and ≈ 174; gray tops at x ≈ 248.5 and ≈ 384 (pitch ≈ 136)
  - gray bottoms end ≈ 2px right of the teal bottoms, leaving a thin gray sliver (as in the banner)
  - teal vertical gradient ≈ `#00cee6` (top) → dark teal (bottom); gray ≈ `#bebebe` → `#737373`
- `logos/wvlet-banner-1280x640.svg` already contains the same four-stroke mark as vector paths with
  `linearGradient`s `#00d2e9 → #045962` (teal) and `#bfbfbf → #737373` (gray). It confirms the
  design and gradient stops; its geometry (240px tall, shear 100.9) is a slightly different rendering
  than the icon PNG, so the icon SVG is fitted to the PNG, not copied from the banner.
- ImageMagick (`magick`, `compare`) is available locally for rasterizing the SVG and computing a
  pixel RMSE against the PNG. No rsvg/inkscape/cairosvg.

## Design

### 1. New asset `logos/wvlet-icon.svg`

- `viewBox="0 0 512 512"` (same canvas as the 512 PNG so it drops in anywhere the PNG is used),
  transparent background, no `width`/`height` so it scales.
- Two `<linearGradient>` defs (`teal`, `gray`) with `gradientUnits="userSpaceOnUse"` spanning the
  stroke's top and bottom y so all strokes of a color share one gradient; stop colors sampled from
  the PNG's top/bottom rows (start from the banner's `#00d2e9/#045962` and `#bfbfbf/#737373`
  and adjust to the sampled values).
- Four `<path>` parallelograms in draw order gray1, gray2, teal1, teal2 (gray behind teal).
  Coordinates derived from the measurements above, refined by sub-pixel edge fitting on the PNG's
  anti-aliased alpha.
- Fit loop: `magick logos/wvlet-icon.svg -background none -resize 512x512 png:-` then
  `compare -metric RMSE` against `logos/android-chrome-512x512.png`; adjust geometry/stops until
  RMSE is low (target: a few percent, dominated by edge anti-aliasing) and a side-by-side
  visual check at 512/64/16px looks identical.
- Also add a README note? No — keep `logos/` as-is besides the new file.

### 2. Mirror into the web asset folders

The repo keeps per-app copies rather than symlinks, so copy the same file to:
- `website/static/img/logos/wvlet-icon.svg`
- `wvlet-ui-main/public/img/wvlet-icon.svg`
- `wvlet-ui-playground/public/img/wvlet-icon.svg`

### 3. Use the SVG on the web surfaces

- `website/docusaurus.config.ts:81` navbar `logo.src` → `img/logos/wvlet-icon.svg`
- `website/src/pages/index.tsx:21` hero `<img src="./img/logo.png">` → `./img/logos/wvlet-icon.svg`
- `wvlet-ui/src/main/scala/wvlet/lang/ui/component/MainFrame.scala:66` navbar icon
  `./img/apple-touch-icon.png` → `./img/wvlet-icon.svg`
- `wvlet-ui-main/index.html` and `wvlet-ui-playground/index.html`: add
  `<link rel="icon" type="image/svg+xml" href="/img/wvlet-icon.svg">` before the PNG favicons
  (browsers that support SVG favicons pick it; the PNG/ICO links remain as fallbacks).
- Delete the unused Docusaurus template `website/static/img/logo.svg` so the only `logo.svg`-ish
  asset in the site is the real Wvlet mark. (Verified by grep: nothing references it.)

### Deliberately unchanged

- `vscode-wvlet/icon.png`: VS Code Marketplace requires a PNG icon; keep it.
- All existing PNG/ICO files (favicons, apple-touch-icon, android-chrome, mstile, `logo.png`),
  `site.webmanifest`, `browserconfig.xml`, README banner: they stay as the raster fallbacks and may
  be linked from outside the repo. Regenerating them from the SVG is a possible follow-up.
- Banner SVGs are already vector.

## Verification

1. `compare -metric RMSE` of the rasterized SVG vs `logos/android-chrome-512x512.png` reported in
   the PR (plus a side-by-side/diff image reviewed visually at 512, 64 and 16px).
2. `pnpm --filter website run build` succeeds (Docusaurus resolves the navbar logo and hero image).
3. `./sbt "ui/compile"` (or the module owning MainFrame.scala) compiles after the src change.
4. `pnpm run build-ui` / `pnpm run build-playground` copy `public/img/wvlet-icon.svg` into `dist/`.
5. Open the built site/playground locally and confirm the SVG favicon and navbar icon render.

## Key decisions

- Fit the SVG to the icon PNG (the canonical mark) rather than reusing the banner's geometry
  verbatim, since the banner strokes are proportioned slightly differently.
- Keep gradients as plain two-stop linear gradients: pixel sampling shows the PNG's shading is a
  linear vertical ramp, so no extra stops or filters are needed.
- Copy the SVG into each app's static folder, following the existing convention of duplicated
  `favicon-*.png` files instead of introducing symlinks or build-time copying.
